# Writing

화면에 들어가는 모든 문구(버튼, 라벨, 안내, 에러 메시지, 빈 상태)의 톤과 작성 규칙이다.

## Writing > 톤 앤 매너

- 문장은 해요체로 통일한다. 예: "저장했어요", "다시 시도해 주세요"
- 하십시오체(~합니다)와 반말은 쓰지 않는다.
- 사용자를 탓하지 않는다. "잘못 입력하셨습니다" 대신 "형식이 맞지 않아요"
- 전문 용어와 내부 용어를 피하고 사용자 언어로 쓴다. "세션이 만료되었습니다" 대신 "로그인 시간이 지나서 다시 로그인이 필요해요"
- 한 문장에는 한 가지 내용만 쓴다.

## Writing > 버튼 문구

- 버튼 문구는 무슨 일이 일어나는지 알 수 있게 "~기"로 끝나는 동사형으로 쓴다. 예: 저장하기, 삭제하기, 보내기, 더보기
- 흐름이 명확한 짧은 표준 문구는 그대로 허용한다: 확인, 취소, 닫기, 다음, 이전, 완료, 로그인, 로그아웃, 회원가입
- 버튼 문구는 공백 포함 10자 이내로 쓴다.
- 마침표, 느낌표 등 문장 부호를 붙이지 않는다.
- 위험한 액션은 대상과 동작을 명확히 쓴다. "확인", "예" 대신 "삭제하기", "계정 삭제하기"
- 진행 중 상태는 "~ 중"으로 바꿔 쓴다. 예: 저장하기 → 저장 중

| 좋은 예 | 피할 예 | 이유 |
|---|---|---|
| 저장하기 | 확인 | 무엇이 확인되는지 알 수 없음 |
| 삭제하기 | 예 | 위험 액션은 동작을 명확히 |
| 다시 시도하기 | 재시도 버튼을 눌러주세요. | 문장형, 문장 부호 |
| 비밀번호 변경하기 | 비밀번호를 변경하시겠습니까 | 질문형 버튼 |

## Writing > 라벨과 placeholder

- 라벨은 명사형으로 짧게 쓴다. 예: 이메일, 비밀번호, 휴대폰 번호
- 라벨에 "~을 입력하세요"를 붙이지 않는다.
- placeholder는 입력 예시로만 쓰고 "예:"로 시작한다. 예: `예: name@example.com`
- 입력 규칙은 placeholder가 아니라 도움말(helper text)에 쓴다.

## Writing > 에러 메시지

에러 메시지는 **원인 + 해결 방법**으로 쓴다.

- 원인: 무엇이 문제인지
- 해결 방법: 사용자가 무엇을 하면 되는지
- 2줄(약 60자) 이내로 쓴다.
- "오류", "에러", "실패"만 단독으로 쓰지 않는다.

| 상황 | 좋은 예 | 피할 예 |
|---|---|---|
| 필수 입력 누락 | 이메일을 입력해 주세요. | 필수 항목입니다. |
| 형식 오류 | 이메일 형식이 맞지 않아요. @를 포함해 입력해 주세요. | 잘못된 입력입니다. |
| 길이 오류 | 비밀번호가 8자보다 짧아요. 8자 이상 입력해 주세요. | 비밀번호 오류 |
| 서버 오류 | 일시적인 문제로 저장하지 못했어요. 잠시 후 다시 시도해 주세요. | 시스템 오류가 발생했습니다. |
| 네트워크 | 인터넷 연결이 불안정해요. 연결을 확인한 뒤 다시 시도해 주세요. | Network Error |

## Writing > 안내와 완료 메시지

- 완료 메시지는 결과를 과거형으로 짧게 쓴다. 예: 저장했어요, 초대 메일을 보냈어요
- 확인 모달 제목은 질문형으로 쓴다. 예: 프로젝트를 삭제할까요?
- 확인 모달 본문에는 그 결과를 쓴다. 예: 삭제하면 되돌릴 수 없어요.

## Writing > 빈 상태 (Empty State)

데이터가 없을 때는 "무엇이 없는지 + 무엇을 하면 되는지"를 쓰고, 가능하면 바로 실행할 버튼을 둔다.

- 예: "아직 만든 프로젝트가 없어요. 첫 프로젝트를 만들어 보세요." + [프로젝트 만들기]
- 검색 결과 없음: "'디자인'에 대한 검색 결과가 없어요. 다른 검색어를 입력해 보세요."

## Writing > 숫자와 날짜 표기

- 천 단위는 쉼표를 쓴다. 예: 1,284건
- 날짜: 같은 해는 "9월 24일", 다른 해는 "2025년 9월 24일"
- 시간: "오후 3:20"
- 단위는 숫자와 붙여 쓴다. 예: 8자, 3개, 10MB
